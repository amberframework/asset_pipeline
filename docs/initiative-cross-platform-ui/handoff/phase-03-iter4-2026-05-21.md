## Two paths

### (A) Dispatch Remediation 3 — author the 12 probe slugs

**Scope (specific, bounded):**

1. Add 12 named scene routes to both `samples/cross_platform/macos_host/hig_showcase.cr` and `samples/cross_platform/ios_host/CrystalHIGHost/` so each binary, when launched with `--scene phase-03-<slug>` (or env var), renders the isolated widget the rubric expects.
2. Author the iOS XCUITest target with `BX1`–`BX12` test methods that launch the host with each slug, drive synthetic taps, and assert state mutations via accessibility queries.
3. Author the macOS AXTest specs in `spec/ui/phase_03_*_spec.cr` that do the same against the macOS host binary.
4. Generate visual baselines (PNGs) for V1–V8 + V10 by running the slugs against the iOS 26.3 sim + macOS 14.x host.

**Estimated cycle:** medium. Probe authoring is mechanical (each is ~50-100 lines of Crystal + ~20-30 lines of XCUITest/AXTest). 12 probes × 2 platforms × 3 artifact types ≈ 1 dispatch.

**Pro:** Phase 3 ships with full empirical proof. The visual-regression infrastructure becomes a reusable foundation Phase 5 (Glass tokenization) and Phase 7 (full visual CI) inherit.

**Con:** Third remediation loop on Phase 3. Pushes Phase 3 close-out into another dispatch cycle. Some of this work duplicates what Phase 7 will own anyway.

### (B) Accept Phase-7 deferral now that the gap is named

**Frame:** The 12 probe slugs are exactly the kind of artifact Phase 7 (Accessibility & Visual Verification Automation) is meant to own. Phase 3's job is to ship the SwiftUI bridge wiring; Phase 7's is to prove it visually + behaviorally with automated CI.

**Architect adjudication that would make this PASS:**

- The 38 Swift tests + 104 Crystal swiftkit specs + 12/12 structural inspection PASSes prove the bridge wiring is structurally complete.
- The 6 captured screenshots + 0 dyld errors at launch prove the binaries actually work — they just lack the 12 named scenes the rubric drives off of.
- BX1–BX12 + V1–V8 explicitly become Phase 7's mandate, with the rubric edited to move them out of Phase 3's `validation.md` and into Phase 7's.

**Pro:** Phase 3 closes now. Phase 4-7 can begin. Phase 7 owns visual-verification infrastructure end-to-end (which it would have inherited anyway).

**Con:** Requires editing `phases/phase-03-swiftui-native-bridge/validation.md` to move the 22 checks. Architect protocol calls editing a frozen rubric "cleanest formally, requires explicit owner sign-off." This is the iter-2 path-(III) move the owner DIDN'T pick then — but at iter 2 the gap looked different (literal-vs-equivalent + missing widget) than it does now (missing probe scenes).

### (C) Hybrid — author the 6 highest-signal probes, defer the rest

Author only the slugs that prove load-bearing Phase 3 invariants:

- `phase-03-action-tap-probe` (BX1, BX2) — proves the action callback trampoline works under SwiftUI hosting. This is THE Phase 3 invariant.
- `phase-03-runtime-override-probe` (BX5) — proves runtime override propagation reaches SwiftUI. Headline invariant.
- `phase-03-button-default` (V1, V2) — proves SwiftUI default supremacy renders.
- `phase-03-button-background-override` (V3) — proves override cascade.

That's 4 probe slugs covering 6 of the 22 BX/V checks; the remaining 16 (toggle/slider/form/sheet probes + V4-V8) defer to Phase 7.

**Pro:** Proves the Phase 3 *headline invariants* empirically while keeping scope tight. The bridge wiring isn't taken on faith.
**Con:** Mixed framing — partial coverage with explicit deferral lines.
